# Relatório 02.1 — Revisão visual e fechamento de pendências

Trabalho direto na `main` (sem branches nem PRs), um push por etapa. Antes de cada commit rodei `lint`, `typecheck` e `test`; antes de cada push, também `build` e `e2e`.

## O que mudou

### 1. Verificação visual das telas que só tinham e2e

- Novo `pnpm visual:app` (`apps/web/scripts/visual-capture-app.mjs`): Playwright com viewport explícito (1440×900 e 1920×1080), dados de exemplo e **data fixada**, então as capturas são reproduzíveis. Salva 30 imagens em `docs/design/screenshots/app/`: calendário, menu “Criar”, popovers (prova e “+N mais”), modal de prova (preenchido e com erro), toast “Desfazer”, as cinco páginas, modais de matéria e filtro de tarefas.
- Inconsistências encontradas e corrigidas (só via tokens/componentes):

| Achado                                                                                | Correção                                                                                                                  |
| ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Filtro de Tarefas esticava na largura toda da página                                  | Envolvido em `self-start` (largura do conteúdo, como o segmentado do calendário)                                          |
| Rádios do modal de excluir matéria usavam o azul nativo                               | `accent-color` amarelo (token) para `radio`/`checkbox`                                                                    |
| Botões secundários com 13 px ao lado de primários de 16 px nas páginas e modais       | `secondary` passa a 14 px; nova variante `outline` (13 px) preserva o botão “Modo Foco” da topbar e o “Desfazer” do toast |
| Capturas pegavam transições de cor no meio (item anterior da sidebar ainda destacado) | O script espera 300 ms antes de cada captura                                                                              |

- Sem problemas encontrados em: alinhamento e espaçamento do menu “Criar”, modais (rótulos, erros, lista de conteúdos), toast, Provas, Matérias, Preferências e Blocos.

### 2. Design system

`docs/design/design-system.md` v0.3, seções 7 e 8: botões (variantes), modal, menu, toast, formulários, lista de conteúdos, abas, estado vazio, estados concluído/cancelado, cores de matéria, tabela de tokens novos e regras de acessibilidade de cada um.

### 3. Telas altas (1920×1080)

Com `@media (min-height: 1000px)` em `tokens.css`: `--ds-chip-pad-y` 3 px → 4 px e `--ds-cell-min-h` 9 rem → 9,4 rem. Medido com Playwright (Nov/2026 com dados de exemplo; Agosto/2026 para 6 semanas):

| Medida                                      | 1920×1080 antes | 1920×1080 depois | 1440×900 (antes = depois) |
| ------------------------------------------- | --------------- | ---------------- | ------------------------- |
| Altura do chip                              | 46 px           | **48 px**        | 46 px                     |
| Linha, mês de 5 semanas                     | 181 px          | 181 px           | 145 px                    |
| Linha, mês de 6 semanas                     | 151 px          | 151 px           | 144 px (o grid rola)      |
| Mínimo de linha (token)                     | 144 px          | **150,4 px**     | 144 px                    |
| Necessário por célula (2 chips + “+N mais”) | 142 px          | 150 px           | 142 px                    |

Decisão: o grid já preenchia a altura; o ganho disponível era nos chips. Eles só crescem até onde **2 chips + “+N mais” ainda cabem em mês de 6 semanas** (151 px). Em meses de 5 semanas sobram ~30 px abaixo dos chips; não mostrei um 3º chip porque exigiria 202 px. Resultado modesto (+2 px), por isso registro como limite do layout atual e não como ganho grande.

### 4. README

Seção **Dados e privacidade** (dados só no navegador, use Exportar, backup automático, navegação anônima) e limitação “testado apenas no Chromium”.

### 5. CI (`.github/workflows/ci.yml`)

- Roda em `push` e `pull_request` na `main`; executa install (cache pnpm), lint, typecheck, test, build e e2e.
- Navegador do Playwright: `actions/cache` em `~/.cache/ms-playwright` (chave = lockfile) + `playwright install --with-deps chromium`. Em falha, os traces do Playwright sobem como artefato.
- **Erro meu corrigido:** a primeira versão tinha `cancel-in-progress` também na `main`, o que cancelou as execuções de dois commits quando fiz push em sequência. Corrigido com `fix(ci)`: só PRs cancelam execuções antigas; na `main` cada commit roda até o fim.
